# Semantic Edge Selection: The Right Way to Apply Fillets and Chamfers

## Why You Should Not Select Edges with SelectByID2

The traditional SolidWorks edge selection approach looks like this:

```python
model.Extension.SelectByID2("Edge1", "EDGE", 0.05, 0.03, 0.0, False, 0, None, 0)
```

Here, `x, y, z` are **magic solid-body coordinates**. This causes two fatal problems:

1. **It breaks as soon as the model changes.** Changing plate thickness or adding a hole shifts all coordinates, causing selection to fail silently.
2. **Failures are silent.** When `SelectByID2` returns `False`, a subsequent `FeatureFillet` call does not raise an error—instead, it applies the fillet to whatever happens to be in the current selection set (which may be empty or leftover from a previous operation), producing hard-to-diagnose feature errors.

## The Right Approach: Select Edges by B-Rep Geometry

`scripts/sw_edge_select.py` traverses the model's B-Rep topology, filters edges by **geometric criteria**, and builds the selection set using each edge object's own `Select2` method. Because it does not rely on auto-generated names or coordinate strings, it remains valid after model rebuilds.

```python
from scripts.sw_edge_select import select_edges
from scripts.sw_part import fillet
from scripts.sw_connect import mm

# 只倒平行于 Z 轴的凸边（即立板的外轮廓竖边）
result = select_edges(model, {"axis": "z", "convex_only": True})
if result["status"] == "ok" and not result["errors"]:
    fillet(model, mm(4))
```

Corresponding MCP tools:

```
solidworks_list_edges  { "axis": "z" }              # 先看有哪些边
solidworks_fillet      { "radius_mm": 4, "axis": "z", "convex_only": true, "dry_run": true }
solidworks_fillet      { "radius_mm": 4, "axis": "z", "convex_only": true }
```

**It is recommended to run with `dry_run: true` first** to confirm that the matched edges are exactly the ones you intend to fillet or chamfer before executing.

## Filter Criteria

| Parameter | Values | Description |
|---|---|---|
| `axis` | `x` / `y` / `z` / `vertical` / `all` | Keep only **straight edges** parallel to the specified axis; `all` disables directional filtering |
| `min_length_mm` / `max_length_mm` | Number | Filter by edge length |
| `circular` | `true` / `false` | Keep only circular edges / keep only non-circular edges |
| `diameter_mm` + `diameter_tolerance_mm` | Number | Filter circular edges by diameter (useful for selecting hole entry edges) |
| `position_mm` + `position_tolerance_mm` | `[x,y,z]` | Edge midpoint must lie near the given coordinates |
| `convex_only` | `true` | Keep only convex edges (external profiles) for outer fillets |
| `concave_only` | `true` | Keep only concave edges (internal corners) for inner fillets |

`convex_only` and `concave_only` cannot both be `true`.

## Typical Usage

**Outer corner fillets on a plate**

```json
{ "axis": "z", "convex_only": true }
```

**Chamfer on a counterbore/hole entry edge** (locate circular edge by hole diameter)

```json
{ "circular": true, "diameter_mm": 6.6, "diameter_tolerance_mm": 0.05 }
```

**Fillet only long edges** (avoid hitting short edges and causing fillet collisions)

```json
{ "axis": "all", "min_length_mm": 50 }
```

**Internal corner fillets on a weight-reduction pocket**

```json
{ "axis": "z", "concave_only": true }
```

## Return Value

```json
{
  "status": "ok",
  "selected_count": 4,
  "selected": [
    { "index": 3, "length_mm": 8.0, "mid_point_mm": [0.0, 0.0, 4.0],
      "is_circle": false, "diameter_mm": null, "convexity": "convex" }
  ],
  "rejected_count": 8,
  "rejected_sample": [ { "index": 0, "reasons": ["方向不平行于 z 轴"] } ]
}
```

`rejected_sample` explains **why** each edge was excluded, making it easy to refine filter criteria rather than blindly loosening tolerances.

**When no edges match, it returns `status: "error"` and never proceeds to create the feature.** This is intentional: continuing silently would apply fillets to unintended edges. The error message includes a suggestion to call `solidworks_list_edges`.

## Convexity Detection

`convexity` is calculated from the normal-vector relationship of the two faces adjacent to the edge. This is a geometric definition of convexity/concavity and does not depend on SolidWorks display settings.

Detection requires reading adjacent face parameters. **If reading fails, `convexity` returns `null` and the edge is not excluded**—preferring over-selection rather than missing an edge the user explicitly requested. In that case, inspect the results with `solidworks_list_edges`.

## Known Boundaries

- Circular edges have no "axial direction," so `axis` filters exclude them; use `circular` + `diameter_mm` to select hole entry edges.
- Tangent edges between faces (such as tangent edges created by an earlier fillet) are returned as normal edges. **When applying multiple groups of fillets/chamfers sequentially on the same model, later groups may pick up tangent edges generated by earlier groups**—run `solidworks_list_edges` before each group to inspect the current topology, or split different feature groups into separate stages.
- Hold-line fillets remain a constrained capability; see `subskills/solidworks-fillet-chamfer-cnc/`.

## API Notes

The second parameter of `IEdge::Select4(Append, Callout)` is a **Callout object**, which must be a Dispatch VARIANT. Passing Python `None` triggers `Type mismatch` (`0x80020005`).

`IEdge::Select2(Append, Mark)` does not have this issue, so the wrapper **prefers `Select2` and falls back to `Select4` only on failure**. Follow the same order when writing custom edge selection code.

```python
# 正确
edge.Select2(True, 0)
# 需要 Select4 时
from scripts.sw_connect import create_empty_dispatch_variant
edge.Select4(True, create_empty_dispatch_variant())
```

## A Pitfall in the Fillet API

`IFeatureManager::FeatureFillet` accepts only **4 parameters**:

```python
model.FeatureManager.FeatureFillet(195, radius, 0, 0)   # (Options, Radius, R1, R2)
```

Do not pass 7 parameters (padding trailing `None` values)—on SolidWorks 2024/2026 this raises `Parameter not optional` (`0x8002000F`). Older documentation and early wrappers contained this bug.

Likewise, the selected edge set must be non-empty; `sw_part.fillet()` explicitly validates the selection set and raises `ValueError` with a hint to use `select_edges()` if nothing is selected.


## Length, Diameter, and COM Compatibility Contract

Edge length must be read via `ICurve.GetLength3(start, end)`; `IEdge` has no `GetLength` method. The official return value of `GetCurveParams2` is 11 doubles: the first 6 elements are start/end point coordinates, indices 6 and 7 are curve parameters, and the final 3 elements are packed integers. Circle radius resides at index 7 of `ICurve.CircleParams` and must not be guessed from edge parameters.

The implementation first obtains `ICurve`, then reads its parameters and validates the official layout and finite numeric values. Reversed edges restore curve parameter order using the packed `SenseFlag`; unknown layouts, invalid parameters, `NaN`, `Infinity`, and non-positive lengths all report errors. Because a short circular arc can have a diameter far larger than its arc length, "diameter on the same order of magnitude as arc length" must not be used as a validity check.

Full circles may lack start/end vertices, in which case validated curve parameter endpoints are used. Straight-line direction uses endpoint differences or the direction vector from `LineParams`—never treat the endpoint coordinates directly as a direction vector. `position_mm` currently compares the midpoint of the start and end points rather than the arc-length midpoint of general curves; locating complex curves requires additional geometric evidence.

When `pywin32` member binding fails, the compatibility path resolves the member ID (DISPID) of `GetCurve` via name binding or type information on the live object before invoking COM, without hardcoding DISPIDs. Some live SolidWorks edge objects do not expose type info; if name binding is also unavailable, an explicit error is raised. Genuine execution errors are not blindly retried as binding failures. Retrieval failures preserve their error details and never masquerade as success with an empty `errors` list.

Automated callers must check `status`, `selected_count`, and `errors` together. Zero matched edges returns an error. Invalid directions, non-finite filter thresholds, and inverted length intervals are rejected.
